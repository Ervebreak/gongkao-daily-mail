# Question Bank Skill

本文件定义“申论真题题库轻接入”的使用边界。题库只服务于“今日一题”的问法和场景参考，不改变邮件产品的主线：当天精读文章仍然是内容中心。

## 1. 目标

题库接入的目标是让“今日一题”更像真实公考题：

1. 借鉴真题的题型、场景、矛盾设置和问法；
2. 避免题目退化成“怎么看高质量发展”这类泛泛讨论；
3. 帮助模型生成更接近申论/机关实务题的训练任务；
4. 保持题目与当天精读文章直接相关。

题库不是素材来源，不是事实来源，也不是邮件中展示给用户的内容。

## 2. 输入来源

当前轻接入只读取 A 类申论题库 CSV：

```text
shenlun_question_bank_v3_a.csv
```

运行时支持两种来源：

```text
QUESTION_BANK_SOURCE=local
QUESTION_BANK_SOURCE=oss
```

默认本地兜底路径：

```text
data/question_bank/shenlun_question_bank_v3_a.csv
```

默认 OSS 对象路径：

```text
question_bank/shenlun_question_bank_v3_a.csv
```

## 3. Fail-open 原则

题库读取失败不能阻断邮件发送。

允许失败的情况包括：

- OSS 文件不存在；
- OSS 鉴权或网络临时失败；
- CSV 字段缺失或编码异常；
- 本地兜底文件不存在；
- 匹配不到合适题目。

处理规则：

1. 记录 `question_bank_warnings`；
2. `question_bank_refs` 置空；
3. 回到旧版“今日一题”生成逻辑；
4. 不把题库失败升级为 P0；
5. 不影响发送、候选存档和管理员报告。

只有当题库异常导致主程序崩溃、候选邮件无法生成或发送链路中断时，才视为程序 P0。

## 4. 匹配原则

题库匹配只做轻量规则匹配，不做 RAG 和向量检索。

优先参考：

- `提出对策 / 对策措施`
- `综合分析 / 解释评价 / 启示分析`
- `归纳概括 / 概括要点`
- `贯彻执行 / 应用文 / 事务文书`

弱化参考：

- `文章写作 / 大作文 / 议论文`

匹配维度：

1. 当天精读文章标题；
2. 当天主题标签；
3. 文章前几段的场景词、治理词、矛盾词；
4. 真题主题标签；
5. 真题题型。

## 5. 输出边界

题库内容只能进入模型 prompt 的隐藏上下文，邮件正文不得展示：

- 真题 ID；
- 年份、地区、卷别；
- 原题来源；
- “本题参考某年某地真题”；
- 完整原题复刻。

今日一题可以学习真题问法，但必须重新生成为独立题目。

## 6. 材料依赖禁止

题库原题里常见的材料依赖表达，不能出现在最终邮件题干中：

```text
根据材料
根据给定资料
结合材料
结合给定资料
给定资料
材料一
材料二
材料三
材料四
材料五
```

最终题目必须脱离原始申论材料也能独立作答。

合格方向：

```text
某地在推进未成年人网络保护工作时，发现平台责任、家长监管和学校教育之间存在衔接不足。假如你是相关部门工作人员，请提出改进建议。
```

不合格方向：

```text
请根据材料三，概括某地未成年人网络保护工作的主要问题。
```

## 7. 作答框架边界

题库接入后，今日一题更容易生成申论式答案。必须继续遵守作答框架压缩规则：

1. `answer_framework / answer_frame` 只写关键词式骨架；
2. 每点不超过 45 字；
3. 格式为“动词短语：简短解释。”；
4. `candidate_answer` 负责完整展开；
5. 作答框架不得与考生版参考答案逐句重复；
6. 不得连续 12 字以上照搬答案表达。

## 8. 元数据沉淀

每次候选生成应尽量写入：

```json
{
  "question_bank_used": true,
  "question_bank_source": "local",
  "question_bank_refs": [],
  "question_bank_warnings": []
}
```

这些字段只用于排查和复盘，不在用户邮件正文展示。

## 9. 复盘标准

周复盘时看三类问题：

1. 题库是否提升了题目的真实感；
2. 是否出现原题泄漏、材料依赖或题目与精读文章脱节；
3. 题库读取失败是否被正确降级，没有阻断发送。
