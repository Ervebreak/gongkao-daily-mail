# 今日一题三层边界规则

本文件专门约束“审题关键 / 作答主线 / 作答框架”的分工。以后修改今日一题 Prompt、质检、渲染或样例时，必须先读本文件。

## 1. 核心结论

> 审题关键看清题，作答主线打开题，作答框架写成题。

三者不是并列重复，而是从“读题”到“构思”再到“落笔”的递进关系。

## 2. 三个模块的固定定位

| 模块 | 底层字段 | 对用户展示 | 负责什么 | 不负责什么 |
| --- | --- | --- | --- | --- |
| 审题关键 | `exam_focus` / `review_key` | 审题关键 | 读题拆题：任务、对象、矛盾、限制、不能漏的角度 | 不展开完整对策，不写“先、再、最后”路线 |
| 作答主线 | `breaking_hint` | 作答主线 | 一句话打开思路：从哪个逻辑切入、按什么顺序展开 | 不列完整分点，不写成第二套框架 |
| 作答框架 | `answer_framework` / `answer_frame` | 作答框架 | 正式分点骨架：3-4条“动词短语：简短解释。” | 不复述审题关键，不逐句重复作答主线 |

## 3. 写法标准

### 3.1 审题关键

合格写法：

```text
这道题不是单纯解释抽检结果，而是要求同时回应消费者疑虑、稳定果农预期、修复监管公信力。作答时要看到“抽检可信度”和“产业声誉受损”两个矛盾。
```

不合格写法：

```text
先公开抽检信息，再完善溯源体系，最后加强长效监管。
```

问题：这已经是作答路线，不是审题。

### 3.2 作答主线

合格写法：

```text
可按照“先释疑稳预期，再溯源查问题，最后建机制管长远”的思路展开。
```

不合格写法：

```text
一是公开抽检流程和复核结果，二是完善产地流通销售追溯，三是建立常态抽检和行业自律机制。
```

问题：这已经变成第二套作答框架。

### 3.3 作答框架

合格写法：

```text
1. 公开信息：说明抽检流程、机构资质和复核结论。
2. 完善追溯：打通产地、流通、销售各环节台账。
3. 健全机制：推动常态抽检、信息公开和行业自律。
```

不合格写法：

```text
先释疑稳预期；再溯源查问题；最后建机制管长远。
```

问题：这只是作答主线的拆开版，缺少正式分点的动作和解释。

## 4. 生成侧要求

1. `exam_focus` 控制在 1-2 句，重点是拆题，不提前作答。
2. `breaking_hint` 控制在 1 句，最多 2 句，优先写成“先X，再Y，最后Z”的总路线。
3. `answer_framework` 控制在 3-4 条，每条不超过 35 字。
4. `candidate_answer` 负责完整展开，不得简单复制 `answer_framework`。
5. 三个模块可以围绕同一问题，但表达层级必须不同：
   - 审题关键说“题目问什么”；
   - 作答主线说“思路怎么起”；
   - 作答框架说“答案怎么分”。

## 5. 质检侧建议

建议 `question_quality.py` 增加以下检查：

| code | 触发信号 | 严重程度 |
| --- | --- | --- |
| `exam_focus_too_answer_like` | 审题关键中出现多个路线词，如“先/再/最后/一是/二是/三是” | medium |
| `breaking_hint_duplicates_framework` | 作答主线与作答框架存在连续 8 字以上重复 | medium |
| `breaking_hint_too_framework_like` | 作答主线出现 2 个以上分号、多个序号或明显分点结构 | medium |

## 6. 渲染侧要求

底层字段可以继续叫 `breaking_hint`，但正式邮件展示建议统一为：

```text
作答主线
```

不再展示为“破题提示”，避免用户误以为这是另一个答题框架。

## 7. 回归检查样例

看到以下输出时，应判定为边界不清：

```text
审题关键：要回应群众质疑，完善监管机制，保护产业声誉。
作答主线：从回应质疑、完善监管、保护产业三个方面展开。
作答框架：一是回应群众质疑；二是完善监管机制；三是保护产业声誉。
```

修正方向：

- 审题关键改成“题目任务 + 相关主体 + 核心矛盾”；
- 作答主线压缩为一句总路线；
- 作答框架改成正式动作分点。
