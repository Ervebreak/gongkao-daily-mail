# 公考晨读生产标准（唯一有效版本）

> 生效范围：选文、生成、质检、定点重写、完整/简版渲染与发布。  
> 冲突规则：本文件与历史规则冲突时，以本文件为准；历史文档仅保留模块实现细节。  
> 目标：让每期内容忠实理解权威文章、可迁移到公考考编场景，并在移动端 5—8 分钟内完成有效阅读。

## 1. 生产链路与共通要求

```text
抓取 → 初筛 → 选文 → 全文拆解 → 公考转化 → 模块生成 → 跨模块统稿 → 质检与定点重写 → 最终发布门禁
```

每一步均应明确输入、输出、硬约束和修复策略。不得用后续润色掩盖选文、事实理解或来源核验的错误。

## 2. 抓取与初筛

### 必备输入

每篇候选至少具备标题、来源及栏目、发布时间、原始链接、完整正文和抓取时间。优先原始发布页，转载页仅作补充核验。

### 硬约束

- 默认保留最近 7 天的内容；候选池不足时依次扩大至最近 48 小时、3 天、7 天，不能降低来源和正文完整性要求。
- 排除图片集、视频/直播页、专题导航、纯公告目录、正文缺失或链接失效的页面。
- 数字、主体、单位和标题/作者字段不得在清洗中混淆或损坏。
- 标题、来源、链接和正文主题必须交叉核验；不一致不得进入生成。

### 初筛

直接排除天气、任免、赛事、突发快讯、纯会议流水、领导活动报道、已屏蔽文章，以及近 7 天已作主文的文章。

进入选文环节的文章应具有完整正文和基础分不低于 10 分。加分因素为权威来源、高价值评论栏目、问题意识、具体对象/场景/矛盾、可支持分析的篇幅及公共治理关联；纯成绩展示、口号化、地方宣传过窄、新闻事实多而机制少、主题/来源高度重复应降权。

## 3. 正式选文

### 评分与门槛

| 维度 | 分值 |
| --- | ---: |
| 公考转化价值 | 30 |
| 问题意识 | 20 |
| 场景具体性 | 15 |
| 矛盾张力 | 15 |
| 材料提取价值 | 10 |
| 权威性与时效性 | 10 |

- 85 分以上：优先主文。
- 75—84 分：可用，但记录短板。
- 低于 75 分：原则上不得作为主文。

主文必须有具体事件或治理场景、明确问题或矛盾、可解释的机制、可迁移的治理路径，并能自然生长出训练题与考场表达。不能只因事件题材冷门而否定文章；应判断其能否提炼出可迁移机制。但标题须呈现上位考点或训练收益，不能只突出冷门事件。

主文仅 1 篇；速读最多 2 篇，补充案例、视角或表达，且不与主文重复。没有合适速读可以少选。

### 历史去重与时间节点

- 主文近 7 天硬去重，速读近 3 天软去重。
- 同时检查主题、核心矛盾、来源和转化角度的语义重复；不同文章不能反复产出同一套治理口号。
- 节日、纪念日、会议等节点只能在文章达到门槛后加分，不能覆盖 75 分主文门槛。
- 文章缺问题意识、机制和转化空间，只能硬贴大标签时，应舍弃重选，不得反复润色硬救。

## 4. 全文拆解与公考转化

必须以完整正文为依据，逐一识别：文章类型、具体事件、主体、场景、表层问题、核心矛盾、发生机制、解决路径、事实/案例/数据和价值立场。

文章结构与考试转化必须分开：

- 原文结构图只忠实展示文章如何展开，通常 3—5 个完整短句，不套“背景—问题—原因—对策—启示”模板。
- 数字必须同时保留对象、单位和含义；不得出现孤立数字。
- 公考转化遵循“具体事件 → 现实问题/冲突 → 主题类别 → 上位考点 → 适合题型 → 作答角度与表达”。
- 保留对象、场景和问题锚点；从个案提炼机制但不得无限拔高。
- “作答角度”回答从什么维度分析；“作答框架”回答具体怎么做；“参考作答”再展开动作、对象、程序和目的。

合格转化须给出表层问题、深层治理逻辑、3—5 个作答角度、适用题型及一句可直接使用的表达。

## 5. 模块生成标准

### 标题、导读与精读

- 标题 12—22 字，最多 26 字；须包含具体对象或问题及考点收益/训练方向，不夸张、不押题、不机械套模板。
- 一句话看懂 50—80 字。
- 三个有用点固定 3 点，分别覆盖表层问题、深层机制、考场迁移。
- 考场用途 1—2 个，明确题型和答案位置。
- 可改写表达 25—55 字，须是完整自然的考生表达。
- 原文阅读提示只写 1—2 句、最多 80 字，明确“点击原文后重点看什么”；不得靠字符裁剪缩短，不得以未完成语义结尾。

同一个比喻、口号或标志性判断原则上只在最合适的模块完整出现一次；不得在精读、题目、答案、金句和 CTA 中换词轮流复述。

### 今日一题

题目必须由主文自然生长，可上升到上位考点但不得脱离核心矛盾；脱离原文也可独立作答；禁止“根据上述材料”“结合给定资料”等不存在材料依赖。

| 题型 | 身份要求 |
| --- | --- |
| 纯申论综合分析题 | 不强制身份；但必须有具体对象、现象/矛盾和任务 |
| 事务处理、公务员实务题 | 必须有明确身份、场景、权限和任务 |
| 结构化面试情景题 | 通常必须有身份与现场冲突 |
| 对策建议题 | 措施必须落在所给身份权限内 |

题干 80—180 字；答题框架 3—4 点，每点**不超过 45 字**；参考作答 280—450 字；30 秒作答 40—100 字；输出模板 60—120 字。

各层职责不得混淆：

- 考查重点：拆对象、任务、冲突和必须回应内容。
- 破题提示/作答主线：一句总路线。
- 答题框架：3—4 个“动词短语：简短解释”的骨架点。
- 参考作答：分 3—4 个短段展开，不能照抄框架。
- 30 秒作答：面试式压缩表达。
- 输出模板：可迁移句式或结构。

机关实务题必须校验职权边界。基层工作人员可调查、协调、提醒、上报、跟踪、依法检查；不得越权制定全国标准、决定重大资金、直接处理侦查司法事项或把协调建议写成可直接拍板。避免“一刀切”、不必要的隐私风险及剥夺申诉/复核渠道。

### 今日可带走

固定采用：

1. 关键词 2—3 个，每个不超过 10 字，必须是具体考点。
2. 常识点 1 个，不超过 100 字，准确可核验。
3. 两句表达，每句建议 28—48 字，最多 60 字，并说明适用题型和答案位置。
4. 方法框架 1 个，不超过 50 字。

淘汰旧的弹性“3—6 项素材清单”口径。金句服务记忆与迁移，不是机械摘抄；不得编造文件、部门、领导讲话或统计数字。

### 政策坐标、速读与 CTA

- 政策坐标仅在高度匹配、来源可核验时展示；弱匹配、出处不明或仅能泛化撑场面的，直接隐藏。
- 《求是》等权威表达不得标注为政策原文。
- 速读最多 2 篇，每篇都须说明可补充的案例、考点、表达或题型价值。
- 简版 CTA 先说明完整版多出的具体内容，再说明适用题型/能力，最后给轻量入口。避免“教你、转化价值极高、避免假大空、干瘪对策词、必看、一定会考”等培训广告话术；不得制造焦虑或罗列全邮件卖点。

## 6. 模块分工与可读性

| 模块 | 唯一职责 |
| --- | --- |
| 主文分析 | 理解原文并完成初步转化 |
| 结构图 | 展示原文真实论证结构 |
| 政策坐标 | 提供高度匹配的外部权威依据 |
| 今日一题 | 训练和输出 |
| 表达总结 | 形成可记忆、可复用资产 |
| 延伸速读 | 补充案例和视角 |

同一段话不得在多个模块换词重复。完整版应按移动端 5—8 分钟控制：重点前置，框架/金句逐条展示，参考答案使用短段，避免连续大段密集文字；用户只读 2—3 个核心模块也应有完整收获。

## 7. 事实安全、质检与定点重写

### 发布门禁

P0 阻断发布：

- 主文未达最低选文标准，正文与来源不一致，或核心意思理解错误。
- 编造政策、数据、法律、部门或权威表述。
- 核心模块缺失；题目严重跑题、不完整或明显越权。
- 结构图明显套模板、孤立数字或不完整。
- 任一最终可见成品出现半截句、开发字段、`None/null/待补充`。
- 跨模块大面积重复。

P1 必须定点修复：标题/导读空泛、考点拔高、题目层级边界不清、关键词宽泛、表达不像考生、中等重复。  
P2 记录优化：个别句子生硬、移动端稍密、非核心模块轻微冗余。

`quality_gate.p0_count` 只统计真正阻断问题。高风险（`severity=high`）不自动等同于 P0；题型、身份、矛盾和政策适配等语义报警必须结合题干和原文复核。

### 定点修复与回退

先定位字段和模块，禁止一发现问题就全文重生成：

| 问题 | 修复方式 |
| --- | --- |
| 选文价值不足、正文不完整、来源/事实无法核验 | 重新抓取或重新选文 |
| 结构图不贴原文 | 仅重拆结构图 |
| 今日一题跑题、身份/权限不稳 | 仅重写今日一题相关字段 |
| 金句/表达不考生化 | 仅重写表达字段 |
| 重复 | 保留最适合的模块，删除或改写其余字段 |
| 半截句、标签泄漏 | 先确定性清洗；无法安全修复再局部生成 |
| 政策匹配弱 | 重匹配；仍不可靠则隐藏 |

修复不得增加新事实、部门、数字、法规和政策；不得无故改变题目身份和权限。修复后必须复查字段完整性、事实安全、重复和对其他模块的影响；若引入新 P0 或质量下降，回退原版本。

### 最终成品与同步

质检对象是用户可见成品，而不是仅检查源 JSON。每次修改后必须：

1. 更新结构化源字段。
2. 重新生成纯文本。
3. 重新渲染完整版 HTML。
4. 重新渲染简版 HTML 和 CTA。
5. 更新质量状态、质量卡与自动修复摘要。
6. 对全部最终可见输出复跑断句、字段泄漏、重复与门禁检查。

只有“无 P0、核心事实可核验、模块职责清楚、句子完整、无明显重复”才能判定可发。
