# Display And Module Boundary Rules

本文件沉淀 2026-05-12 至 2026-05-14 内测反馈中的展示、重复和模块边界问题。凡涉及 `email_renderer.py`、纯文本/HTML 渲染、模块增删和跨模块去重，应先读本文件。

## 1. 模块边界

1. 文章框架图只展示文章真实展开结构，不额外加入“考场迁移”“这类题怎么用”节点。
2. “考场迁移”价值优先放在“记住3个点”“今日一题”或“今日可带走”的可迁移框架中。
3. `exam_tags` 只作内部考点标签，不在框架图底部单独展示，也不得改写成框架图 step。
4. `exam_use` 展示“换成考场话”，只放本篇文章观点如何转成考场分析语；`rewritable_expression` 展示“可用表达”，只放以后同类题可复用的短句。
5. 如果同一观点同时出现在框架图、今日一题和今日可带走，应优先保留在最适合的模块，其他模块压缩或换角度。

## 2. 标签不进正文

正式内容项中不得带栏目标签。以下词只能由渲染层统一生成，不得出现在模型字段正文里：

- 换成考场话：
- 考场话：
- 可用表达：
- 必备金句：
- 参考句式：
- 适用场景：
- 考场迁移：这类题怎么用

如果字段正文含上述标签，质检应报 `label_leaked_in_expression` 或对应模块标签泄漏 code。

## 3. 禁止显示层硬裁半句

1. 渲染层不得为了“看起来短”而固定字数裁剪小标题、金句、适用场景和考场话。
2. 如必须压缩，优先在句号、问号、感叹号、分号处收束；不能收束时应回到生成层重写。
3. 小标题过长时允许自然换行，不允许裁成“企业负”“全程留”“形式主”这类半截词。

## 4. 三版本同步

一次修复必须以 `brief` 为单一源头重新渲染 `plain_text` 和 `html_body`。禁止只改 JSON、只改 HTML 或只改纯文本。

发送前应确认：

- 框架图 step 数、label 和 content 在 JSON/纯文本/HTML 三处一致。
- “今日一题”“今日可带走”“速读”关键字段在三处一致。
- 手动修复文件不是旁路文件，早晨触发器实际读取的是候选件路径。

## 5. 典型反例

- 框架图第 5 步写“考场迁移：这类题怎么用”，下方又显示“可迁移考点”。
- “换成考场话”卡片正文以“可用表达：”开头。
- HTML 中小标题被裁成“随意检查加重企业负”。
- 本地改了 `latest_fixed.json`，但 `morning_send` 仍读取旧候选件。

## 8. 题库元数据展示边界

题库接入产生的以下字段只允许出现在候选 JSON、质检 JSON、管理员报告或日志中：

```text
question_bank_used
question_bank_source
question_bank_refs
question_bank_warnings
question_bank_count
question_bank_match_tokens
```

用户邮件正文不得展示：

- 真题 ID；
- 真题年份；
- 地区/系统；
- 卷别/类别；
- 题库来源文件；
- “参考某道真题”。

如果需要在管理员报告里展示题库信息，应明确标为“内部排查字段”，不得混入用户可见 HTML。
