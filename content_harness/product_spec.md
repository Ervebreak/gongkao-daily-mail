# 公考晨读邮件项目产品规格说明 SPEC

## 1. 产品名称

公考晨读邮件

暂定名称：

```text
公考晨读｜每日官方文章拆解
```

项目定位不是新闻订阅，也不是普通早报，而是面向公考、考编用户的**每日备考材料整理服务**。

---

## 2. 一句话定位

每天自动筛选官方媒体文章，并将其拆解为公考/考编可直接使用的申论、面试、公基备考材料，通过邮件定时发送给用户。

更具体地说：

```text
把人民日报、新华社、半月谈、人民网评、浙江宣传等官方文章，
拆成考生能看懂、能记住、能写进申论、能说进面试的材料。
```

---

## 3. 项目目标

本项目的目标不是让用户“多看几篇新闻”，而是帮助用户完成以下转化：

```text
官方文章 → 考点主题
政策评论 → 答题框架
新闻案例 → 申论素材
文章表达 → 可背金句
热点内容 → 面试/申论题目
每日积累 → 周/月复盘资料
```

最终希望用户每天用 5-10 分钟，完成一次轻量化官方文章积累。

---

## 4. 目标用户

主要用户包括：

1. 正在准备公务员考试的用户；
2. 正在准备事业单位、考编、选调、三支一扶等考试的用户；
3. 申论素材积累薄弱、不知道每天该读什么的人；
4. 面试备考中缺少热点案例、答题表达和场景化题目的人；
5. 没有时间主动筛选人民日报、新华社、半月谈、浙江宣传等官方文章的人；
6. 希望通过碎片时间持续积累官方表达和答题素材的人。

用户不一定会完整阅读每封邮件，但应能从每封邮件中至少带走一个有用点：

```text
一个热点判断
一个答题框架
一道场景化题目
一句可用表达
一个案例素材
```

## 4.1 用户阅读行为假设

内测反馈显示，用户并不一定会完整阅读每封邮件，而是会根据个人备考需求选择性阅读。高频被关注的模块包括：文章框架图、今日一题、今日可带走、必备金句、今日精读中的“考场怎么用”。

因此，邮件设计应遵守以下原则：

1. 每个模块应能独立提供价值；
2. 重点信息必须前置；
3. 用户即使只看 2-3 个模块，也应获得明确收获；
4. 不强迫用户点击原文，但应为愿意深读的用户提供原文入口；
5. 邮件应适合晨起、通勤、吃早饭、学习前的 5-10 分钟快速阅读。

---

## 5. 核心价值

本产品为用户节省五类成本：

| 成本 | 用户原本要做什么 | 产品替用户做什么 |
|---|---|---|
| 筛选成本 | 每天自己找文章 | 自动筛选适合公考的官方文章 |
| 理解成本 | 自己读懂文章主旨 | 提炼文章主题、主线、考点 |
| 整理成本 | 自己摘金句、做笔记 | 自动整理关键词、金句、表达 |
| 转化成本 | 自己思考怎么用于答题 | 转化为申论/面试题、框架和答案 |
| 复盘成本 | 自己保存和回看 | 自动生成每日归档和周 PDF |

产品真正提供的不是“邮件”，而是：

```text
每日官方文章筛选 + 公考化拆解 + 可复盘素材沉淀
```

---

## 6. 内容来源

优先抓取和使用以下官方或准官方媒体内容：

1. 人民日报；
2. 新华社；
3. 人民网评 / 人民锐评；
4. 半月谈；
5. 浙江宣传；
6. 光明网；
7. 人民论坛；
8. 其他适合公考素材积累的官方评论、政策解读、基层治理类文章。

其中，半月谈、人民网评、浙江宣传、人民日报评论类文章优先级较高。

文章选择应优先考虑：

```text
基层治理
公共服务
民生保障
乡村振兴
生态文明
数字治理
营商环境
高质量发展
干部作风
社会治理
法治建设
青年奋斗
产业发展
```

应降低以下内容权重：

```text
纯会议报道
纯活动通稿
纯宣传稿
纯国际新闻
纯娱乐文化资讯
考试转化价值弱的科技资讯
与公考申论/面试关联较弱的普通新闻
```

## 7. 产品形态

当前阶段主要包括两种交付形态：

### 7.1 每日晨读邮件

每天早上定时发送，用户通过邮箱接收。

每日邮件定位：

```text
轻量、及时、手机友好、可直接积累。
```

重点是让用户当天快速完成一次素材输入。

### 7.2 周末 PDF 汇编

每周一次，将一周每日晨读内容汇编成 PDF，随周末或指定日期晨读邮件附带发送。

当前阶段 PDF 定位：

```text
一周每日晨读完整汇编。
```

当前不强行做“真题练习区、素材摘抄区、框架迁移区”等模块化月刊，因为每日邮件模块仍在迭代。等每日模块稳定后，再升级为专题化、月刊化资料。

---

## 8. 每日邮件模块结构

### 8.0 模块优先级

根据内测反馈，当前阶段每日邮件模块分为三级：

#### 一级核心模块

1. 文章框架图；
2. 今日一题；
3. 今日可带走 / 必备金句 / 可用表达；
4. 今日精读中的“考场怎么用”。

这些模块直接决定用户是否认为邮件对备考有价值，应优先保证质量、完整性和可读性。

#### 二级辅助模块

1. 今日 3 件事；
2. 一句话看懂；
3. 今日速读；
4. 原文链接。

这些模块用于降低阅读门槛、扩展素材面和满足深读需求。

#### 三级运营模块

1. 反馈尾注；
2. PDF 提示；
3. 内测说明。

这些模块应尽量轻量，不得干扰主体阅读。

每日邮件原则上包含以下模块。

### 8.1 顶部主题卡

作用：

```text
让用户一眼知道今天讲什么、为什么值得看、和考试有什么关系。
```

主题卡应避免过于宏观。

不推荐：

```text
高质量发展
基层治理
生态文明
```

推荐：

```text
数字赋能欠薪治理
县域发展不能复制粘贴
监管失灵背后的政绩观偏差
劳动价值如何托举新质生产力
```

主题卡应该是“当天化、考场化、问题化”的表达。

### 8.2 今日 3 件事

作用：

```text
给时间有限的用户一个 30 秒快速入口。
```

应包含：

1. 今日主题；
2. 今日最值得记住的表达或判断；
3. 今日一题或今日训练方向。

要求：

```text
必须真的是 3 个清晰信息点；
不得只是后文大段重复；
每一点都要能独立阅读。
```

### 8.3 今日精读

作用：

```text
将一篇官方文章拆解成公考/考编可用材料。
```

应包含：

1. 精读文章标题；
2. 来源；
3. 原文链接；
4. 一句话看懂；
5. 文章主线；
6. 核心观点；
7. 考场怎么用；
8. 可直接改写的表达；
9. 如果点原文，重点看哪里。

今日精读不能只是摘要。

不合格方向：

```text
这篇文章主要介绍了……
文章指出……
文章强调……
```

合格方向：

```text
这篇文章可以用于回答“数字治理如何提升基层服务能力”类题目。
它最有价值的不是新闻事实，而是提供了“入口前移—数据预警—闭环监管—制度兜底”的治理框架。

#### 原文阅读双路径

产品不强制用户阅读原文。邮件应同时支持两种使用路径：

1. 快速路径：用户只看一句话看懂、文章框架图、今日一题、今日可带走，也能获得备考价值；
2. 深读路径：用户点击原文后，对照邮件框架理解文章结构，进一步积累原文表达。

因此，原文链接应尽量可用；如链接不稳定，应提供“文章标题 + 来源”的备用搜索提示。

### 8.4 文章框架图

作用：

```text
帮助用户快速看懂文章结构，并将文章结构迁移为申论/面试答题框架。
```

文章框架图必须贴合原文，不得为了高级感强行重构。

优先依据：

1. 原文小标题；
2. 原文段落推进顺序；
3. 原文论证逻辑；
4. 原文案例与结论之间的关系。

要求：

```text
每个节点必须是完整短句；
不得出现孤立数字；
不得出现半句话；
不得机械套用“背景—问题—原因—对策—启示”；
不得把原文三段结构强行拆成五六段；
如使用数字，必须带完整单位和语境。
```

示例：

不合格：

```text
农民工视频连线工会调解员，1天
拖欠12
15
```

合格：

```text
01｜云端维权：通过智能舱、线上调解等方式，让劳动者少跑腿、快拿钱。
02｜数据预警：通过多部门数据联动，提前发现欠薪风险，把问题处置在早。
03｜工资闭环：通过工资专户、总包代发、实名制管理，让工资支付有账可查。
04｜制度兜底：通过法律监督、信用惩戒、司法联动，让欠薪者跑不了、赖不掉。
```

### 8.5 今日一题

作用：

```text
将当天精读文章转化为申论或面试训练题。
```

今日一题必须具体化、场景化、矛盾化、任务化。

题目原则上应包含四个要素：

```text
身份
场景
矛盾
任务
```

不合格：

```text
你怎么看高质量发展？
你怎么看基层治理现代化？
谈谈你对数字治理的理解。
```

合格：

```text
你是街道工作人员，辖区内部分劳动者反映欠薪维权流程复杂、跑腿次数多，企业又认为自身经营困难，短期内难以一次性支付。领导让你牵头推动数字化欠薪治理服务，你会怎么开展工作？
```

今日一题应包含：

1. 题型；
2. 题目；
3. 审题关键；
4. 作答框架；
5. 考生版参考答案；
6. 30 秒压缩表达；
7. 一句话可带走。

其中“考生版参考答案”必须像普通优秀考生能说出口，不得写成政策报告、论文摘要或领导讲话。

### 8.6 今日可带走

作用：

```text
让用户当天至少记住几个可直接迁移的表达、素材或框架。
```

应包含：

1. 关键词；
2. 高频常识点；
3. 必备金句；
4. 可直接改写的表达；
5. 可迁移框架；
6. 适用场景。

重点不是“列出金句”，而是告诉用户：

```text
这句话适合什么题？
能放在开头、分析、对策还是结尾？
能替换掉什么空话？
考场上怎么写/怎么说？
```

不合格：

```text
金句：治理要有温度。
适用场景：基层治理。
```

合格：

```text
原来的空话：要提升基层治理水平。

可以改成：
基层治理不能只停留在流程上，更要把群众诉求、资源配置和制度保障衔接起来，让治理既有速度，也有温度。

适用场景：
可用于基层治理、公共服务、民生保障类申论小题或面试综合分析题。
```

### 8.7 今日速读

作用：

```text
提供 1-2 篇补充文章，扩展同主题或相关主题素材。
```

今日速读不追求长，但必须说明考试价值。

每篇速读应包含：

1. 标题；
2. 来源；
3. 一句话摘要；
4. 考场可用点；
5. 可积累表达或案例。

不合格：

```text
这篇文章介绍了某地推进某项工作的情况。
```

合格：

```text
这篇不用精读，记住一个用法即可：如果遇到“基层服务数字化”“群众办事少跑腿”类题目，可以用它作为数字治理提升公共服务效率的案例。
```

### 8.8 内测反馈尾注

邮件中可以保留轻量反馈引导。

但反馈尾注应简短，避免打扰阅读。

建议形式：

```text
如果今天这封对你有帮助，可以直接回复：
1 有用
2 太长
3 今日一题不错
4 框架图不错
5 最近没怎么看
```

周 PDF 中不得重复展示每日反馈尾注，只在最后统一保留一次反馈说明。

## 9. 周 PDF 定位

### 9.1 当前阶段 PDF 原则

当前阶段，周 PDF 应优先定位为“一周每日晨读完整汇编”，而不是重新加工后的专题小册子。

原因是每日邮件模块仍在迭代，如果过早按“真题练习区、素材摘抄区、框架迁移区”等方式重组，容易造成内容缺失或用户感觉“邮件里有的内容，PDF 里没有”。

因此，当前周 PDF 应优先满足：

1. 按日期完整收录每日晨读主要内容；
2. 适合打印、保存、周末集中复盘；
3. 不重复展示每日反馈尾注；
4. 不出现测试说明、技术字段、乱码、空白页；
5. 保证正文可读、字号适中、模块层级清晰。

### 9.2 后续月刊方向

等每日模块结构稳定后，可以进一步探索月刊/特刊电子版，按主题重新整理：

1. 本月高频热点；
2. 本月精读文章；
3. 可背金句与可用表达；
4. 申论/面试题型关联；
5. 地方案例；
6. 真题映射；
7. 框架迁移。

当前阶段周 PDF 的基本定位为：

```text
一周每日晨读完整汇编。
```

它的作用是：

1. 帮助用户周末集中复盘；
2. 保留每日邮件内容；
3. 方便打印、收藏、回看；
4. 为后续月刊、专题资料打基础。

当前阶段不做过度加工，不强行按模块重组。

PDF 应包含：

1. 封面；
2. 本周目录；
3. 每日晨读完整汇编；
4. 统一反馈说明。

PDF 不应包含：

```text
每日重复反馈尾注
测试说明
not_found
待补充
第X条
Python 列表格式主题
乱码项目符号
空白首页
```

未来模块稳定后，可升级为：

```text
热点专题版
真题关联版
素材摘抄版
表达积累版
月刊电子版
```

## 10. 内容质量标准

### 10.1 内容长度与模块去重原则

每日邮件不追求大而全，而追求“每天至少有 2-3 个可带走点”。

允许用户选择性阅读，但不允许因模块堆叠造成以下问题：

1. 同一观点多处重复；
2. 今日精读和今日可带走内容重复；
3. 金句在多个模块重复出现；
4. 模块过多但重点不突出；
5. 用户看完后不知道应该记住什么。

内容可以较丰富，但必须层级清晰、重点明确、可跳读。

各模块分工应保持清楚：

- 今日精读负责解释文章为什么有考试价值；
- 文章框架图负责展示文章结构，不额外加入“考场迁移”节点；
- 今日一题负责把文章转化为训练场景；
- 今日可带走负责沉淀关键词、金句、表达和框架；
- 今日速读负责补充相关素材，不重复精读内容。

### 10.2 合格邮件标准

一封合格邮件至少满足以下标准：

1. 精读文章适合公考/考编场景；
2. 今日主题具体，不空泛；
3. 文章框架图贴合原文；
4. 框架图节点完整，无孤立数字；
5. 今日一题具体，有身份、场景、矛盾、任务；
6. 今日一题答案像考生能说出口；
7. 金句和表达说明考场用法；
8. 今日速读说明考试价值；
9. 邮件适合手机阅读；
10. 不出现占位符、乱码、重复字段；
11. 正式发送后保存 JSON/HTML 归档；
12. 周 PDF 能完整汇编一周内容。

## 11. 禁止出现的问题

正式邮件和 PDF 中禁止出现以下问题：

```text
1. “待补充”
2. “第X条”
3. “适用场景：适用场景：”
4. Python 列表格式，如 ['基层治理', '民生保障']
5. 孤立数字，如“1天”“12”“15”
6. 半句话结尾，如“但”“并且”“由于”
7. 今日一题过于宏观
8. 框架图脱离原文结构
9. 金句没有说明怎么用
10. 速读只有摘要，没有考试价值
11. PDF 空白首页
12. PDF 每天重复反馈尾注
13. 邮件中出现明显技术日志或程序字段
14. 标题、链接、来源明显不匹配
15. 同一模块内大段重复
```

## 12. 生成流程

当前推荐生成流程如下：

```text
1. 抓取官方文章
2. 程序按来源、日期、历史、标题、正文长度、主题进行初筛
3. 大模型第一阶段选择精读文章和速读文章
4. 程序提取精读文章较完整正文
5. 大模型第二阶段生成邮件结构化内容
6. 进行质量检查
7. 渲染 HTML 邮件
8. 测试模式只发测试邮箱
9. 正式模式发送给 active 用户
10. 保存 JSON/HTML 归档
11. 周指定日期生成 PDF 汇编
12. 记录发送日志和质量问题
```

后续应逐步增加：

```text
知识库检索
真题库参考
历史优秀样例参考
质量问题规则注入
不合格模块自动重写
```

## 12. 申论真题题库轻接入规格

### 12.1 产品定位

题库接入不是把邮件改成“刷题产品”，而是让每日阅读更系统化：用户通过一篇文章，同时看到文章主线、考场转化、真题式问法和可复述答案。

因此题库只增强“今日一题”，不改变邮件的核心定位：

- 主内容仍来自当天官方文章；
- 今日一题仍服务于当天文章；
- 题库只提供隐藏问法参考；
- 不在邮件正文展示题库来源。

### 12.2 用户价值

题库接入解决三个问题：

1. 题目不再过泛，更接近真实申论问法；
2. 用户能从碎片化阅读慢慢建立“文章 → 题目 → 答案”的系统训练链路；
3. 题目场景、矛盾和任务更稳定，有利于形成长期答题思维。

### 12.3 非目标

当前阶段不做：

- 真题原文展示；
- 真题答案解析；
- 用户刷题记录；
- 题库搜索页；
- 向量检索/RAG；
- 自动生成套卷；
- 邮件中标注“参考某道真题”。

### 12.4 运行配置

默认配置：

```text
QUESTION_BANK_ENABLED=true
QUESTION_BANK_SOURCE=local
QUESTION_BANK_LOCAL_PATH=data/question_bank/shenlun_question_bank_v3_a.csv
QUESTION_BANK_OSS_KEY=question_bank/shenlun_question_bank_v3_a.csv
QUESTION_BANK_MATCH_LIMIT=3
QUESTION_BANK_RECENT_DAYS_DEDUP=7
QUESTION_BANK_FAIL_OPEN=true
```

线上推荐：

```text
QUESTION_BANK_SOURCE=oss
QUESTION_BANK_OSS_KEY=question_bank/shenlun_question_bank_v3_a.csv
```

`QUESTION_BANK_OSS_KEY` 是 OSS bucket 内部对象路径，不是本地路径，也不是完整 URL。

### 12.5 数据边界

题库文件应放在现有邮件系统 bucket 内，不需要新建 bucket。

示例：

```text
oss://gongkao-mailer-erve/question_bank/shenlun_question_bank_v3_a.csv
```

题库读取只读 OSS，不写订阅表，不触发邮件发送，不改历史记录。

### 12.6 成功标准

题库接入后，合格邮件应满足：

- 今日一题更像真题，但不泄漏真题；
- 题干没有“根据材料/材料三”等材料依赖；
- 题目与精读文章仍直接相关；
- 题库失败时邮件仍能正常候选和发送；
- candidate / quality JSON 能追踪题库使用情况。


## 定版覆盖规则（2026-08）

完整版的移动端阅读时长统一为 **5—8 分钟**，不再采用“5—10 分钟”口径。模块结构、用户价值和展示细节如与 [公考晨读生产标准](gongkao_morning_reading_production_standard.md) 冲突，以该标准为准；尤其须坚持主文 1 篇、速读最多 2 篇、政策坐标弱匹配隐藏、用户只读核心模块也能获得完整收获。
