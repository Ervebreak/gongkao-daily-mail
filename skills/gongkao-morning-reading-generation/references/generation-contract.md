# 生成技能契约

## 输入

最低输入包括候选文章的标题、来源/栏目、发布时间、原始链接和完整正文；以及最近主文、速读、主题和来源的去重信息。

可选输入包括当天时间节点、政策坐标库、题库问法参考、已有 JSON schema 与渲染字段。它们只能辅助决策，不能覆盖主文质量和事实安全要求。

## 输出

输出是待审核的结构化晨读候选件，而不是邮件发送动作。候选件应能映射到项目既有 JSON schema，并至少包含：

- 标题、主题与顶部导读；
- 1 篇主文的准确元信息、精读、结构图与考试转化；
- 0—2 篇速读及各自考试价值；
- 1 道由主文自然生长的今日一题；
- 固定格式的今日可带走；
- 仅在可靠时展示的政策坐标；
- 完整版和简版渲染所需字段，包括简版 CTA。

输出同时记录简短的生成说明，供审核链路使用；这类说明不得进入邮件正文。

## 停止条件

以下情况不应继续硬生成：

- 主文低于选文门槛，缺少具体问题/机制，或不能自然形成训练题；
- 正文、标题、来源或链接无法相互核验；
- 所需事实、政策或法律出处无法核验；
- 没有合适速读或政策坐标：允许对应模块为空，不能凑数。

## 与审核技能的边界

生成技能产出候选件并保留字段级重写能力。独立审核技能决定是否可发、问题等级、是否阻断，并检查最终渲染成品。审核发现问题后，生成技能只处理被定位的字段；如果根因是选文或原文事实，退回选文/核验阶段。
