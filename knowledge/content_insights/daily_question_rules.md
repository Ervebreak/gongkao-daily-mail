# 今日一题规则库

> 用途：约束每日邮件中的“今日一题”模块，让题目更像真题、答案更像考生、作答边界更像真实机关工作。

---

## 1. 四要素规则

### 规则

今日一题优先具备四个要素：

1. 身份：你是谁。
2. 场景：事情发生在哪里。
3. 矛盾：具体问题是什么。
4. 任务：要求你做什么。

### 推荐题干结构

```text
近期，某地/某区/某单位出现【具体问题】，群众/媒体/学生/企业反映【具体矛盾】。假如你是【具体身份】，领导要求你【具体任务】，你会怎么做？
```

### 不推荐

```text
请谈谈你怎么看未来产业发展。
请结合材料谈谈基层治理的重要性。
```

### 推荐

```text
近期，某区多条盲道存在断点、被占用和设计不合理问题，残障人士反映出行不便。假如你是区城管局工作人员，领导要求你提出整改建议，你会从哪些方面入手？
```

## 2. 具体场景优先规则

### 规则

题目要从一个具体治理场景切入，再上升到上位考点。

### 好题方向

- 垃圾中转站建而不用。
- 盲道被占与摆拍舆情反转。
- 校园周边高糖高油高盐零食泛滥。
- 自行车进地铁试点引发管理讨论。
- 基层干部调解家庭矛盾反映首办责任。

### 风险题方向

- 直接问数字经济、未来产业、基层治理、健康中国等宏大概念。
- 没有具体身份、具体对象、具体任务。
- 只要求“谈看法”，没有可操作场景。

## 3. 作答框架骨架化规则

### 规则

`answer_framework` 每点控制在 45 字以内。完整展开应放入 `candidate_answer`。

### 写法要求

- 每点只写：动作 + 对象 + 目的。
- 不写完整长句。
- 不堆多个从句。
- 不在框架里写成小作文。

### 不佳案例

```text
推行红色标签警示制度：在货架和包装上加贴醒目标识，用简单文字提示高盐高油高糖风险，帮助家长孩子直观识别。
```

### 推荐修改

```text
风险提示：在货架、价签、提示牌标明高糖高盐风险。
```

## 4. 基层身份权限边界规则

### 规则

如果题干身份是基层市场监管所、街道、社区、城管、基层工作人员，答案必须区分：

1. 可以直接执行的事项。
2. 需要建议上级推动的事项。
3. 必须依法查处、有明确依据的事项。

### 可以直接写

- 摸排台账。
- 现场检查。
- 风险提示。
- 消费引导。
- 联合约谈。
- 问题上报。
- 回头看复查。
- 群众反馈。

### 慎写或改写

| 风险写法 | 稳妥写法 |
|---|---|
| 基层直接推行包装红色标识 | 建议上级探索风险提示制度，先在货架、价签、消费提示牌试点 |
| 对持续售卖高糖高油食品的商户依法处罚 | 对三无、过期、标签不规范、虚假宣传、无证经营等违法违规问题依法查处 |
| 基层制定行业标准 | 梳理问题并向上级提出完善标准建议 |
| 要求企业研发健康产品 | 引导企业优化供给，或建议行业主管部门推动 |

## 5. 机关答案口吻规则

### 规则

考生版答案要像普通考生能写出来的话，而不是政策文件或评论文章。

### 推荐风格

- 先表明态度或工作思路。
- 再分步骤讲具体动作。
- 每一步有对象、有抓手、有结果。
- 少用空泛词，多用可执行动作。

### 避免风格

- “提高政治站位”“强化顶层设计”“形成强大合力”等空话堆叠。
- “第一第二第三”后面仍然是宏观口号。
- 超出身份权限的宏观部署。

## 6. 题目与精读文章强关联规则

### 规则

今日一题必须与精读文章的主线强关联。不能只借上位词，不能跑成通用基层治理题。

### 检查方式

至少命中以下两类信息：

1. 精读文章具体对象：如垃圾中转站、盲道、校园周边零食。
2. 精读文章核心矛盾：如建而不用、被占难用、标准不清、监管衔接不畅。

### 典型失败

```text
精读文章讲校园周边零食治理，题目却写成某项目审批把关不严、整改不到位。
```

### 修复方向

把题目改回具体对象：校园周边商户、重口味零食、高糖高油高盐、学生健康、基层市场监管。

## 7. 30 秒输出规则

### 规则

30 秒输出不应成为第二个完整答案，只训练一个小能力。

它必须是一句完整、可直接开口复述的表达，不能是半截框架，也不能是教研指令。

### 推荐训练目标

- 写一句开头表态。
- 写一句问题判断。
- 写一句对策收束。
- 写一句身份代入。

### 不推荐

- 要求复述完整作答框架。
- 要求一次性说完所有对策。
- 句子超过 120 字。
- 以分号、冒号、逗号、顿号结尾。
- 只写“一是、二是”，没有第三点或总结收束。

### 典型失败

```text
整改直指“重装备轻管理”的要害。一是严禁核心工程外包，外包队伍考核不合格即清退；二是打通部门数据壁垒，让电力、通风等数据自动预警、联合核查；
```

### 推荐修改

```text
整改要从“设备升级”转向“管理升级”：一是严禁核心工程外包，二是打通关键数据预警，三是做实培训考核和违法惩戒，用制度刚性兜住安全底线。
```

## 8. 字段标题泄漏规则

### 规则

今日一题字段里的 `exam_focus`、`breaking_hint` 等只存正文，不存栏目标题。

### 禁止

```text
审题关键：任务是提出落地工作建议……
作答主线：先讲清楚是什么……
```

### 推荐

```text
任务是提出落地工作建议，对象是辖区超龄劳动者和用人单位，核心矛盾是信息不对称和执行意愿不足。
先讲清楚是什么，再帮双方对接落实，然后建立日常监督和兜底维权渠道。
```

---

## 维护规则

1. 新增题型案例时，必须标注身份、场景、矛盾、任务四要素是否齐全。
2. 如果题干身份为基层人员，必须运行“权限边界”检查。
3. 如果 `answer_framework` 每点超过 45 字，应压缩为关键词式骨架。
4. 如果今日一题跑题，应优先重写题目和框架，不必重写整封邮件。
5. 如果 `thirty_second_answer` 半截，应优先字段级修复，不重写整道题。
6. 如果 `exam_focus` / `breaking_hint` 携带栏目标题，应规则清洗，不交给模型自由重写。
