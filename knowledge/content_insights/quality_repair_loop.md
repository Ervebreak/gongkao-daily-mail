# 邮件成品清洁度与修复闭环规则

> 用途：沉淀 2026-05-26 至 2026-05-28 多次手工修复 `latest.json` / `candidate_email.html` 后暴露出的共性问题。本文不是运行代码，而是后续改 prompt、checker、renderer、rewrite 回滚策略时的知识依据。

---

## 1. 字段契约：模板负责标题，字段只存正文

### 规则

邮件 HTML / plain_text 的栏目标题由 renderer 统一渲染，`brief` 字段值只存正文内容。

字段值开头不得保留同名栏目标题，例如：

- `featured_article.original_reading_focus` 不得以“如果点原文，重点看”开头。
- `featured_article.rewritable_expression` 不得以“可用表达”开头。
- `daily_question.exam_focus` 不得以“审题关键”开头。
- `daily_question.breaking_hint` 不得以“作答主线”或“破题关键”开头。
- `today_takeaway.framework` 不得以“可迁移框架”开头。

### 错误理解

```text
字段里不要出现两个标题，只保留一个标题。
```

### 正确理解

```text
字段里一个栏目标题都不能保留，因为模板会再渲染标题。
```

### 典型错误

```text
标题：可用表达
正文：可用表达：保障特定群体的权益……
```

### 正确修法

```text
标题：可用表达
正文：保障特定群体的权益，不能简单套用旧标准……
```

## 2. 缺句号与半截句必须分开处理

### 缺句号

如果一句话语义完整，只是缺少句末标点，可以自动补中文句号。

```text
这篇文章把校园周边零食治理转化为未成年人保护和基层监管考点
```

可修为：

```text
这篇文章把校园周边零食治理转化为未成年人保护和基层监管考点。
```

### 半截句

如果句子停在未完成结构上，不能只补句号，必须补全意思或阻断。

高风险结尾包括：

- 可落地
- 可用于
- 适合转化为
- 主要包括
- 从而
- 进而
- 同时
- 并且
- 还有争议
- 一是
- 二是
- 三处
- 三点
- 一方面
- 另一方面

### 典型错误

```text
如果点原文，重点看三处：一是煤矿通过阴阳图纸、真假监控、幽灵矿工绕开监管的具体手段；
```

### 正确修法

```text
重点看三处：一是煤矿通过阴阳图纸、真假监控、幽灵矿工绕开监管的具体手段；二是外包施工、培训流于形式导致智能设备管不好；三是电力、通风、监控等数据没有共享预警，暴露出技术升级背后的管理短板。
```

## 3. 30 秒输出必须完整收束

### 模块定位

`daily_question.thirty_second_answer` 是考生可直接开口复述的一句完整表达，不是第二套作答框架，也不是教研指令。

### 禁止形式

- 以 `；`、`：`、`，`、`、` 结尾。
- 只有“一是、二是”，没有第三点或总结收束。
- 写成“请用30秒复述……”这类训练指令。
- 完全复述 `answer_framework` 的每一条。

### 推荐结构

```text
这道题的核心是……：一是……；二是……；三是……，最终……。
```

### 典型错误

```text
整改直指“重装备轻管理”的要害。一是严禁核心工程外包，外包队伍考核不合格即清退；二是打通部门数据壁垒，让电力、通风等数据自动预警、联合核查；
```

### 正确修法

```text
整改要从“设备升级”转向“管理升级”：一是严禁核心工程外包，二是打通关键数据预警，三是做实培训考核和违法惩戒，用制度刚性兜住安全底线。
```

## 4. 修复闭环：发现问题不等于修复成功

### 必须形成闭环

```text
发现问题
→ 字段级修复或模块重写
→ 写回 brief
→ 重新渲染 plain_text / html_body
→ 重新跑 final quality
→ quality_card 只展示最终剩余问题
```

### 典型流程 bug

```text
content_quality 发现 framework 半截
→ rewrite 记录显示已修复
→ 但最终 html_body 仍是旧半截句
```

### 修复要求

1. 修复必须写回 `brief` 本体。
2. 修复后必须重新执行 `render_plain_text` 和 `render_email_html`。
3. 质检卡必须基于最终结果生成，不能混入已修复的旧问题。
4. `latest.json`、`plain_text`、`html_body`、`quality_gate`、`quality_card_markdown` 必须指向同一版内容。

## 5. 回滚策略：硬错误修复不得被综合分误伤

### 问题

有时字段级修复已经补全半截句，但内容审稿模型综合分下降，系统把修复整体回滚，导致半截句重新进入最终邮件。

### 规则

以下硬错误修复，只要修复后不再触发同类问题，应优先保留，不应因综合评分轻微下降而回滚：

- `truncated_answer`
- `suspected_truncated_sentence`
- `truncated_takeaway`
- `duplicate_display_prefix`
- `display_label_prefix`
- `label_leaked_in_expression`
- `missing_sentence_terminal_punctuation`
- `leading_colon`

### 推荐策略

```text
硬错误修复：字段修好就保留。
表达优化修复：综合分明显下降才回滚。
模块重写修复：复检关键字段，不合格则只回滚该模块或继续字段级小修。
```

## 6. P0/P1/P2 分级原则

### P0：必须阻断发送

- 今日一题答案或关键展示字段明显半截。
- 今日一题缺任务、严重跑题、过于宏大。
- 精读主文链接完全不可用且无备用提示。
- 关键模块空缺或 HTML 缺失。
- 明显开发标记、异常字段泄漏。

### P1：需要修复，但可人工判断

- 字段栏目标题泄漏。
- 原文重点看、可用表达、审题关键等展示字段轻微重复。
- 模块表达明显撞车但不影响理解。
- 速读链接不可用但有标题/来源可搜索。

### P2：体验优化，不应阻断

- 速读 SSL warning 且有标题/来源/备用搜索。
- 模块轻度相似。
- 作答框架略长。
- 30 秒输出略长但完整。
- 金句轻微相似。

## 7. 模块角色边界

### 金句、可用表达、考场迁移的分工

| 模块 | 角色 | 写法边界 |
|---|---|---|
| `today_takeaway.golden_sentences` | 可摘抄、可背诵、有文采 | 负责“记住一句话” |
| `featured_article.rewritable_expression` | 考场可改写表达 | 负责“写进答案” |
| `featured_article.exam_use` / `usable_for_exam` | 考场迁移说明 | 负责“告诉用户怎么用” |
| `today_takeaway.framework` | 方法论提炼 | 负责“提供答题框架” |

### 规则

同一主题可以在多个模块出现，但不能同句式、同关键词密集复用、同功能重复。

如果和金句撞车：

1. 优先改 `exam_use`，让它写成“这篇文章适合迁移到什么题、从哪几个角度答”。
2. 其次改 `rewritable_expression`，让它写成考场表达而不是金句摘抄。
3. 尽量保留 `golden_sentences`，因为它是用户最容易收藏的内容。

---

## 8. 维护规则

1. 新增质量案例时，优先沉淀规则，不只沉淀某一句修改。
2. 每个规则应说明：错误表现、根因、正确修法、代码落点。
3. 质量修复优先顺序：半截句 > 字段标题泄漏 > 链路写回一致性 > 分级策略 > 模块表达优化。
4. 如果同一问题连续出现 2 次以上，应从 prompt 约束升级为字段级规则或 checker。
