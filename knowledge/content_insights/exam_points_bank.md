# 高频考点与可迁移框架库

> 用途：为今日一题、申论对策框架、面试表达、周报 PDF 的“高频考点地图”提供可复用框架。

---

## 1. 建管并重五步法

### 适用场景

- 垃圾中转站、公厕、健身器材、文化广场、养老设施、便民服务站等公共服务设施。
- 民生工程建成后闲置、低效、损坏、无人维护。

### 问题本质

重建设、轻运营；重投入、轻绩效；重短期显绩、轻长期使用。

### 作答框架

1. 前期调研：建设前充分征求群众需求。
2. 资金测算：同步考虑建设资金和运维资金。
3. 主体明确：明确谁建设、谁运营、谁维护、谁监督。
4. 运维保障：建立财政补助、社会参与、第三方运营等机制。
5. 群众评价：将使用率、满意度和投诉反馈纳入考核。

### 可用表达

- 民生工程不能止于建成，更要落在管好用好。
- 公共服务设施既要建得起来，也要管得下去、用得起来。

## 2. 真问题不能被假事件遮蔽

### 适用场景

- 网络摆拍、公益造假、网红翻车、舆情反转、平台流量乱象。
- 个案造假背后仍有真实民生痛点。

### 问题本质

个别虚假事件消耗社会信任，但真实治理短板不能被一并否定。

### 作答框架

1. 依法惩治造假，维护公共秩序和社会信任。
2. 压实平台审核、推荐、标识和处置责任。
3. 回到真实痛点，防止治理焦点跑偏。
4. 补齐公共服务短板，回应群众真实诉求。
5. 建立信息核验、公众反馈和舆情复盘机制。

### 可用表达

- 打击造假是治标，解决真实痛点是治本。
- 不能因为个别造假消耗了同情，就忽视真实存在的民生困境。

## 3. 无障碍设施建而难用治理框架

### 适用场景

- 盲道、坡道、电梯、适老化设施、公共交通无障碍、政务服务无障碍。

### 问题本质

设施“有没有”不等于服务“好不好用”。问题常在断点、占用、设计不合理和维护不到位。

### 作答框架

1. 摸排断点：查清盲道断头、坡道缺失、电梯故障等问题。
2. 清理占用：整治车辆、摊点、杂物占用无障碍设施。
3. 微改造优化：对设计不合理、衔接不顺畅的点位改造。
4. 网格巡查：纳入城管、社区、物业日常巡查。
5. 公众反馈：开通随手拍、热线、无障碍体验员反馈渠道。

### 可用表达

- 无障碍设施不能停留在“有没有”，更要落到“好不好用”。
- 城市温度不只体现在宏大工程里，也体现在每一处方便通行的细节中。

## 4. 校园周边治理五步法

### 适用场景

- 食品安全、文具盲盒、烟卡、游戏充值、校外摊贩、交通秩序、噪声扰民。

### 问题本质

校园周边的小风险，容易演变为未成年人保护和基层治理的大问题。

### 作答框架

1. 摸排台账：排查校园周边商户、摊贩、重点商品和问题点位。
2. 依法查处：查三无、过期、虚假宣传、无证经营、标签不规范等违法违规行为。
3. 风险提示：通过货架、价签、提示牌等方式加强消费提醒。
4. 家校协同：学校开展健康教育、家长参与监督反馈。
5. 常态复查：定期回头看，防止整治后反弹。

### 可用表达

- 校园周边治理不能只盯校门口几米路，更要看背后的监管、教育和家庭引导。
- 对未成年人保护，既要末端查处，也要前端预防。

## 5. 基层身份权限边界框架

### 适用场景

- 题干身份为基层所、街道、社区、城管、市场监管、普通工作人员、调研组成员。
- 任务为整治建议、工作思路、调研建议、向上级汇报。

### 基层工作人员能写

1. 摸排：排查点位、建立台账、梳理问题清单。
2. 检查：依据现有法规开展现场检查。
3. 提示：设置消费提示、风险提醒、宣传引导。
4. 约谈：对重点商户、责任主体开展提醒约谈。
5. 上报：对标准、法规、跨部门问题提出建议。
6. 协调：联动教育、卫健、城管、社区、物业等部门。
7. 复查：开展回头看，形成闭环。
8. 反馈：回应群众诉求，公开整改进展。

### 基层工作人员慎写

1. 直接制定行业标准。
2. 直接修改包装规则。
3. 没有违法依据就处罚商户。
4. 越权要求企业研发产品。
5. 直接决定财政资金、重大制度和跨部门政策。

### 稳妥表达

- 建议上级探索风险提示制度。
- 先在货架、价签、消费提示牌等环节试点。
- 对三无、过期、标签不规范、虚假宣传、无证经营等违法违规问题依法查处。
- 对普通风险事项，加强提示、引导、约谈和协同治理。

## 6. 邮件模块角色边界

### 适用场景

- `today_takeaway.golden_sentences`、`featured_article.rewritable_expression`、`featured_article.exam_use`、`today_takeaway.framework` 之间出现表达重复、功能撞车。
- 质检提示 `module_role_overlap`、`repeated_expression_across_modules`、`near_duplicate_expression`。

### 问题本质

同一文章可以在多个模块反复出现同一主题，但不能让多个模块承担同一个功能。模块角色不清会造成用户感觉“邮件在重复说同一句话”。

### 模块分工

| 模块 | 角色 | 应该怎么写 |
|---|---|---|
| `today_takeaway.golden_sentences` | 可摘抄、可背诵、有文采 | 负责“记住一句话” |
| `featured_article.rewritable_expression` | 考场可改写表达 | 负责“写进答案” |
| `featured_article.exam_use` / `usable_for_exam` | 考场迁移说明 | 负责“告诉用户这篇文章怎么用” |
| `today_takeaway.framework` | 方法论提炼 | 负责“提供答题框架” |

### 典型错误

```text
exam_use：技术升级不能替代管理升级，装备越先进越需要人员、制度、监管。
golden_sentence：设备越先进，越需要匹配专业的人、规范的制度和管到底的监督。
```

这两句虽然不完全相同，但功能高度重叠，都在承担“金句式表达”。

### 推荐修法

保留金句，把 `exam_use` 改成使用说明：

```text
这篇文章适合迁移到安全生产、技术治理、监管协同类对策题，可从责任压实、人员培训、数据共享、执法闭环四个角度展开。
```

如果 `rewritable_expression` 与金句撞车，优先改 `rewritable_expression`，让它更像考场表达：

```text
技术赋能不能只算设备账，还要算管理账、人员账和监管账；否则，越先进的工具，越可能放大旧治理漏洞。
```

### 维护规则

1. 金句尽量保留，除非存在硬伤。
2. `exam_use` 撞车时，优先改成“可迁移题型 + 作答角度”。
3. `rewritable_expression` 撞车时，优先改成“能写入申论/面试答案的表达”。
4. `framework` 不写金句，写方法论或答题路径。

---

## 维护规则

1. 框架必须能迁移到多篇文章和多类题。
2. 作答框架以“动作 + 对象 + 目的”为主，不写成长答案。
3. 涉及基层身份时，必须区分“可直接执行”“可建议上级”“需依法查处”。
4. 后续每新增一个高频考点，应配至少一个反例，防止模型写空话。
5. 模块角色边界属于产品质量规则，优先通过字段级改写和质检分级控制，不宜轻易升为 P0。
