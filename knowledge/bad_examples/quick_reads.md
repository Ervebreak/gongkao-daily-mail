# Bad Examples: Quick Reads

## BR-001 无考试价值速读

### 反例

```text
本文介绍了某地推进科技创新的相关情况，值得关注。
```

### 问题

- 只是新闻摘要。
- 没有说明考点。
- 没有说明案例价值。
- 没有说明可用表达。
- 没有说明适合什么题型。

### 修复方式

```text
可作为“因地制宜发展新质生产力”的案例素材，适合用于产业升级、科技创新、县域发展类申论分析题。
```

## BR-002 只有标签，没有解释

### 反例

```text
适用于申论、面试、公基。
```

### 问题

适用范围太宽，等于没有说明价值。用户不知道这篇速读到底该怎么用。

### 修复方式

写清楚“考点 + 用法”：

```text
可补充“基层治理精细化”的案例，用于说明发现问题要靠前、处置问题要精准、反馈问题要闭环。
```

## BR-003 缺少一句话概括

### 反例

```json
{
  "title": "某篇速读文章",
  "exam_value": "可用于规范市场秩序、平台治理和诚信生态建设类申论题。",
  "one_sentence": ""
}
```

### 问题

- 用户只看到考试价值，看不到文章本身讲了什么。
- 邮件会退化为“题型标签集合”，不像晨读素材。
- 如果只依赖模型重写，可能因 quick_reads repair 不闭环而反复 P0。

### 修复方式

缺 `one_sentence` 时按以下顺序兜底：

```text
summary > reason > exam_value
```

同时要求 `one_sentence` 是文章核心内容概括，`exam_value` 是考试转化价值，两者分工不能混同。
