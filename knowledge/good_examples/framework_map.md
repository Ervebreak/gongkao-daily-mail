# Good Examples: Framework Map

## GF-001 贴合原文结构的框架图

### 示例

```text
1. 从群众高频需求切入，说明公共服务直接关系生活感受。
2. 分析资源不足、流程不顺、协同不够带来的服务短板。
3. 提出补齐资源、优化流程、压实责任的改进路径。
4. 落到治理能力提升，让政策温度转化为群众获得感。
```

### 为什么好

- 每个节点都是完整短句。
- 没有孤立数字、半句话或抽象标签。
- 顺序符合“问题切入 -> 短板分析 -> 路径提出 -> 治理落点”。
- 能帮助用户把文章结构迁移成申论分析框架。

### 可复用规则

框架图优先复刻原文逻辑，不为了高级感重构文章。节点控制在 3-5 个，每个节点必须是完整短句。


## GF-002 政策解读类 / 数字治理类框架图

### 示例

```text
文章类型：政策解读类 / 数字治理类
主线：网络法治不是给技术发展“踩刹车”，而是给数字社会立规则、稳秩序、兜底线。

01 为什么要讲网络法治？
新技术发展快、平台影响大、数字生活覆盖广，单靠市场自发运行，容易出现算法滥用、低价内卷、权益受损、数字鸿沟等问题。

02 第一层：给新技术划边界
面对人工智能、算法推荐、数据使用等新技术，法治的作用是明确规则边界，让创新在可预期、可约束的轨道上发展。

03 第二层：给平台竞争立秩序
平台经济不能只拼流量、低价和规模，还要治理强制低价、恶意补贴、不正当竞争等问题，让市场竞争回到公平有序轨道。

04 第三层：给弱势群体兜底线
数字治理不能只服务“跑得快的人”，也要照顾老年人、未成年人、新就业形态劳动者等群体，避免技术便利变成新的门槛。

05 落点归纳：法治护航数字社会稳步前行
文章最后回到网络法治的治理价值，强调既要保护创新活力，也要维护市场秩序和群众权益。
```

### 为什么好

- 五个节点都对应文章真实内容，没有额外加入考场迁移节点。
- 每个节点都有本篇文章独有信息，不是万能句。
- 用户能看懂文章怎样展开，迁移价值再交给今日一题或今日可带走承接。
